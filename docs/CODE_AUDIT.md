## 2. 检查的代码模块

- `components/dc_base`：平台抽象、网络地址解析、内存分配，重点关注 FreeRTOS 栈是否需要片内 DRAM、PSRAM 分配行为和构建差异。
- `components/fl_filter`：对不可信规则行、正则、二进制索引进行边界检查；测试有效/无效规则、恶意格式、超长与溢出限制。
- `components/dns_core`：DNS 报文、EDNS、TCP/UDP、缓存、TTL、上游结果、并发合并、负缓存及失败重试。
- `main`：ESP-IDF 专有代码的 API 与资源生命周期**静态审查**，包括初始化/任务栈、更新失败、证书与私钥、OTA、管理端认证、Flash A/B 配置。
- `web`：通过 Node 对嵌入 JavaScript 做语法校验；后续仍需真浏览器端到端验收。
- `tools/tests`：主机编译和健壮性测试；Go 兼容性参照工具需要较新 Go 工具链，本次未构建。
- `docs`：Markdown 站内链接、代码围栏、文档与现存 API 对照。文档检查脚本随仓库提交，**只在主机/CI 执行，不进入 ESP32 固件**。

## 5. 本次代码调整（保持轻量）

- DoH POST 现在严格要求 `application/dns-message`，避免缺失 Content-Type 时误认为合法 RFC 8484 请求。
- Web 认证互斥锁分配失败时中止启动，避免运行后触发空指针/非法互斥锁访问。
- 规则更新任务第一次因内部 RAM 不足无法创建时，报告明确错误；管理界面再触发更新可重试启动任务。
- 更新配置时若无法分配“新配置快照”，不再先将新配置写入持久存储而在运行态失去同步。
- 备份恢复时 TLS 证书/私钥写入 NVS 的失败不再被无条件忽略。
- 去除重复的 `stdlib.h`、调整误导性的 DMA 预留注释，均不影响运行逻辑。
- 同步整理 README、API 与架构文档，扩展详细使用指南。

这些修改遵守“没有新增常驻监控线程、诊断缓冲或周期性扫描”的要求。**因本次缺少 ESP-IDF 工具链，ESP 平台代码的这些修改只完成静态审核，没有真机编译确认**。

## 6. 已知剩余风险与待硬件验证

1. **ESP-IDF 5.5.x 交叉编译尚未执行**：函数签名、Kconfig、分区和可用栈大小必须由官方工具链检查。
2. **Wi-Fi 与 HTTPS/DoT 并发内存**：应用首启、两个 HTTP 服务、规则更新和 TLS 握手是否能同时分配任务栈需要真机确认。
3. **DoT 当前是单连接顺序处理**：外网大量并发场景下可能有队首阻塞；不应宣传为高并发公共 DNS 服务。
4. **Flash 与 PSRAM 共享缓存**：更新、外排序、镜像切换期间的 Cache Error/任务栈位置必须上板复测。
5. **NVS 中的证书私钥不保证静态加密**，管理 HTTP 仍可用明文访问，公网暴露存在风险。
6. **真实协议极端场景**：DNSSEC 大报文、EDNS、多帧 TCP、异常链、DoH POST/GET、OTA 回滚需要实机和网络侧联调。
7. **兼容性差异**：少数复杂规则语义与 Go 参照版本可能存在边界差异，详见兼容性表。

## 7. 安全注意事项与待完善项

- 文件覆盖清单是**可追溯的纳入审查范围证明**，不代表 100% 逐行逻辑正确或所有跨模块调用路径均经过动态执行。
- HTTP 管理仍未默认强制 TLS，任何可能含密码/私钥的 `/api/*` 操作都应只在可信网络使用。
- TLS 证书和私钥分别保存时发生中途故障可能只成功一半，更新路径仍可继续改造成原子版本；目前需要通过启动时的配对检查防止错误证书生效。
- 下载订阅与 OTA 的 HTTPS 服务端身份验证、超时、跨版本分区和断电场景，需在 ESP-IDF 环境中逐项实机确认。
- 片内最大连续可分配堆与 SRAM 最小余量必须真机验收；调试可使用已有统计 API，无需新增常驻监测任务。
