# 架构设计

> 本文档由 AI 整理生成。

## 1. 总体

```
             ┌───────────────────── ESP32-S3 (2 × 240 MHz) ─────────────────────┐
 客户端 ──UDP/TCP──▶ dns-rx 线程 ──▶ dns_handle()                                     │
             │        │  ACL → 限速 → 解析 → 本地记录 → 过滤(fl_match) → 缓存 ─┐      │
             │        │                 │拦截/重写/本地/缓存命中：直接回复      │      │
             │        │                 ▼                                       ▼      │
             │        │            sendto()                         dns_forward() 待决表 │
             │        │                                              （合并相同问题）    │
             │ dns-up 线程 ◀── 上游 UDP 应答（ID→槽位、源地址、问题校验）◀── 上游      │
             │   dns_complete(): 规范化 → 缓存 → 响应过滤 → 逐个等待者回复            │
             │ dns-stream 线程: 截断重试 TCP / tcp:// 上游                            │
             │ DoT 工作线程: 持久 TLS + 流水线    DoH 工作线程 ×2: keep-alive POST     │
             │ httpd: Web/API/DoH 端点   rules-upd: 订阅下载 + 编译 + 切换             │
             └───────────────────────────────────────────────────────────────────────┘
```

可移植部分（`dc_base`、`fl_filter`、`dns_core`）只通过 `dc_port.h` 访问平台，同一份代码既能编进固件，也能在 Linux 上编译成单元测试、`dnsd_host` 和 `flc`。

## 2. 查询流水线（dns_engine.c）

1. **访问控制**：`local_only` 时只接受私有、链路本地和回环地址，以及 `allow` 中列出的网段，其余请求直接丢弃。
2. **限速**（可选）：按客户端 IP（IPv6 按 /64）的令牌桶。
3. **解析**：用边界检查的解析器处理报文，只接受向前的压缩指针并限制跳数。异常报文分别返回 FORMERR、NOTIMP 或 BADVERS，非查询报文直接丢弃。
4. **本地记录**（优先级最高，与 AdGuard Home 的 DNS 重写一致）：
   - 精确名称走哈希表，通配符 `*.x` 取最长后缀匹配。
   - 本地 CNAME 链会在表内继续解析，然后应答「原名 CNAME 终点 + 终点记录」。终点不在本地时，转发终点并在答案前补上 CNAME。
   - 名称存在但没有该类型的记录时返回 NODATA；值写成 `-` 时，该类型交给上游。
5. **过滤**（`fl_match`，只读，线程安全）：
   - 文本形式超过 253 个字符、无法检查的名称（二进制标签写成 `\DDD` 后变长）在开启拦截时直接返回 REFUSED，不会未经检查就转发。
   - **拦截**：按 AdGuard Home 的 `genDNSFilterMessage` 构造应答。A/AAAA 按拦截模式返回 0.0.0.0、::、自定义 IP、NXDOMAIN 或 REFUSED；hosts 规则返回规则中的 IP；其他类型返回 NODATA+SOA（null_ip 模式下返回空的 NOERROR）。
   - **$dnsrewrite**：RCODE 或资源记录直接应答。CNAME 重写会转发目标名称，再在答案前补上 CNAME（对应 `processFilteringAfterResponse`）。
   - **例外或白名单**：转发，并且不做响应过滤。
   - 全局保护关闭时只有重写规则生效（`FL_REQ_REWRITES_ONLY`）。
6. **缓存**：键为（小写名称、类型、类、DO 位、CD 位）。命中后在接收线程内直接回复，回复前逐条递减 TTL、恢复客户端名称的大小写、按客户端的 EDNS 设置附加 OPT，UDP 超长时截断。
7. **响应过滤**（AdGuard Home `filterDNSResponse`）：依次检查应答中的 CNAME 目标、A/AAAA 地址和 HTTPS 记录的 ipv4hint/ipv6hint。缓存条目保存规则代际相关的过滤备忘，帮助避免不必要的重复工作。
8. **转发**：分配等待者，相同的未决问题直接挂到同一个待决项上（合并），否则新建上游请求。

所有拦截、重写和本地应答都在 UDP 接收线程中完成，不涉及线程切换和锁等待。每个查询只获取一次配置快照（`view_t`，引用计数），读取过滤器、本地记录和配置时都不用加锁。

## 3. 上游管理（dns_server.c）

- **待决表**：上游查询 ID 是 16 位随机数，通过 65536 项的 ID→槽位表做 O(1) 匹配。每个待决项按问题哈希分桶，用来合并相同问题。应答必须同时满足 ID、来源地址和端口（属于发过请求的上游）以及问题（类型、类、名称）都匹配。
- **防伪造（DNS 0x20）**：发给上游的名称随机改变字母大小写，UDP 应答必须原样重复，伪造应答更难碰中。某个上游连续 8 次改变了大小写时，判定它不保留大小写，只对它关闭这项检查。
- **票据**：TCP/DoT/DoH 的结果用票据（代际 + 尝试序号 + 上游编号 + 槽位）报告，迟到的旧尝试不会被记到当前上游头上，一次失败也只计一次。
- **策略**：
  - `fastest`（默认）：选平滑 RTT 最低的上游，并以 1/16 的概率随机探测其他上游。
  - `load_balance`：按 1/RTT 加权随机。
  - `parallel`：同时发给两个上游，取先到的应答。
- **超时**：单次尝试的超时为 `min(3×SRTT+60 ms, upstream_timeout)`，最少 150 ms，超时后换下一个上游重试；总超时后返回 SERVFAIL。连续失败 3 次的上游会暂停 1 s、2 s、4 s……最长 30 s。连接被拒绝、发送失败等立即失败的尝试会马上换上游；只剩失败过的上游时，重试间隔 250 ms 起逐次加倍，不会形成重试风暴。
- **SERVFAIL / REFUSED**：还有没问过的可用上游时，这类应答算作该上游的一次失败，立即换上游重试；所有上游都这样回答时才把它交给客户端。
- **截断**：上游 UDP 应答带 TC 标志时，改用 TCP 向同一上游重试。
- **缓存写入**：去掉上游的 OPT，ID 清零，TTL 按 min/max 设置限制。正应答按最小 TTL 缓存；NXDOMAIN 和 NODATA 按 SOA 的负缓存 TTL 与应答中其他记录（例如前面的 CNAME）的最小 TTL 缓存（RFC 2308），没有 SOA 时不缓存。SERVFAIL 和截断应答不缓存。
- **乐观缓存**：过期但仍在 `optimistic_max_age` 内的条目先以 TTL 30 返回，同时在后台刷新。刷新得到的确定应答（NOERROR/NXDOMAIN）不可缓存（例如 TTL 为 0）时，旧条目立即删除，不会继续返回旧地址。
- **TCP**：每条消息的收发都有总时限（客户端 5 s、上游 2×上游超时），逐字节慢发的对端占不住线程。
- **停止**（主机测试和 `dnsd_host`）：先让所有在途查询以 SERVFAIL 结束、关闭阻塞中的连接，等线程全部退出后再释放；30 s 内仍未退出时宁可不释放，也不留下悬空指针。
- **同步接口** `dns_server_query()`：供 TCP、DoH 端点和诊断使用。同步槽位用票据防止超时后的迟到写入。

## 4. 两级缓存（dns_cache.c）

- **L2（PSRAM）**：环形缓冲区按 FIFO 淘汰，没有碎片；开放寻址索引用回移删除，负载不超过 3/4。每个条目保存 TTL 字段的偏移，读取时只改这些字段。
- **L1（内部 SRAM）**：直接映射，缓存小于 512 B 的热门应答，L2 命中时晋升。读 L1 不访问 PSRAM。
- 运行中把缓存大小改成 0 会真正关闭缓存；内存不足时退回最小尺寸或关闭，不会留下半初始化的状态。
- 修改过滤规则**不需要**清空缓存：缓存里只有上游原始应答，过滤判定在每次查询时重新计算。

## 5. 规则引擎与镜像格式（fl_filter）

编译器以流式方式解析规则（逐行，不保留原文），然后：

1. 规则分类：
   - **普通域名规则**（`||d^`、`|d^`、`.d^`、hosts 等 8 种形状，加上例外和 important 标志）编码成键上的位掩码。
   - **带修饰符的域名规则**挂到键上，作为「复杂规则」。
   - **通配符和正则规则**编译成程序。
2. 外部排序：设备端内存块装满（默认 192 KiB）后排序并写成 run，run 存放在 staging 分区，以 4 KB 扇区链表组织（空闲表回收、原地压缩合并），最后多路归并去重。
3. 生成镜像：

```
header(512 B, CRC) | BLOOM | SAMPLES | BLKOFF | ONELABEL | KEYS | HOSTSETS |
CRULES | GENERIC | BADFILTER | SOURCES | POOL | SYMTAB
```

- 键是标签反转的主机名（`ads.example.com` 变成 `com.example.ads`），因此查询名称的每一级都是同一字符串的前缀，一次遍历就能得到所有级别的哈希。
- **BLOOM**：分块 Bloom 过滤器（32 B/块，每键 12 位）。不命中就直接跳过，命中后一定走精确比对，不会误判。
- **KEYS**：前缀压缩块，每块 16 键，后缀用 FSST 风格符号表压缩。SAMPLES（每块首键前 8 字节）复制到内部 RAM 做二分查找。
- **GENERIC**：通配和正则规则的 2/3/4-gram 预过滤哈希表、必检列表和字面量预检（memmem）；程序以 DFA（≤256 状态）或 Pike VM 形式运行（RE2 子集，与 Go regexp 一致）。
- **BADFILTER**：运行时 `$badfilter` 身份表（跨镜像、带条件的）。

镜像整体有 CRC32 校验，头部另有 CRC，加载时会验证所有偏移。匹配时同时查询多个镜像（自定义规则镜像 + 订阅镜像），并按 AdGuard 优先级合并：白名单列表 > `$dnsrewrite` > important 例外 > important 拦截 > 例外 > 拦截 > hosts。

## 6. 规则更新流程（main/rules.c）

1. 检查变化：每个订阅发一次带 If-None-Match / If-Modified-Since 的条件请求。全部返回 304 且订阅集合没变时不重建（省流量，也省 Flash 擦写）。
2. 重建：HTTPS 流式下载，边下载边送入编译器。run 写到 staging，镜像写到**非活动**槽位。Flash 写入时首次触及的扇区才擦除，64 KB 整块空闲时整块擦除。
3. 失败处理：只要任何启用订阅下载或编译失败（包括首次下载），整次更新失败，旧已提交镜像不变，约 30 分钟后重试。HTML 页面和截断的下载都会被识别并拒绝。
4. 激活：
   - 先用 `esp_partition_mmap` 把新镜像映射进来并完整校验，立即切换过去，这时从 Flash 读。
   - 旧的 PSRAM 副本在进行中的查询结束后自动释放。
   - 然后把新镜像复制到 PSRAM 并再次切换。
   - 整个过程中 PSRAM 不会同时存在两份镜像，过滤也不会中断。
   - 映射窗口期间持有 Flash 锁，任何 Flash 写操作都要等待，因为直接读 Flash 映射时不能同时写 Flash。切换到 PSRAM 副本后，要等最后一个还在用映射镜像的查询结束（映射真正解除）才释放 Flash 锁。PSRAM 不足时会先缩小缓存；仍然不够时停用订阅规则并报错，而不是冒风险从 Flash 读。
5. 自定义规则单独编译成一个 RAM 镜像，保存后立即生效，不用重建订阅。

## 7. 固件运行环境

- **XIP from PSRAM**：将部分指令和只读数据复制映射到八线 PSRAM，以降低一些 Flash 访问造成的阻塞；它**不能保证 Flash 擦写期间无缓存停顿**。尤其规则更新、MMAP 切换及 TLS/Flash SDK 路径可能依赖缓存关闭时仍可访问的内部 DRAM 栈，**当前相关线程使用内部 DRAM 栈**。更新期间的 DNS 长尾延迟仍需实机测试。
- **线程优先级**：dns-rx 和 dns-up 为 10，DoT/DoH 为 9/8，TCP 和 stream 为 5，httpd 为 4，更新为 2。
- **Wi-Fi**：STA 模式，`WIFI_PS_NONE`，国家码 CN；断线后按 0.2 s 到 10 s 指数退避重连。没有配置或 60 s 连不上时打开配置热点（AP+STA，热点开启期间每 15 s 重试一次，避免扫描打断热点）。所有状态切换都在事件循环任务中执行（定时器只投递事件）。保存网络设置时，先回复网页请求，0.5 s 后再应用；只改引导 DNS、NTP 或时区时不会断开 Wi-Fi。
- **配置热点 / 强制门户**：只能通过热点访问设备时，DNS 服务器对热点网段（192.168.4.0/24）的所有 A 查询都返回 192.168.4.1，其他类型返回空应答；Web 服务器把未知路径（如 `/generate_204`、`/hotspot-detect.html`）302 重定向到首页，手机连上热点后会自动弹出配置页。STA 连上后，如果仍有手机连在热点上，热点再保留 3 分钟，让配置页能显示设备的新地址。
- **设备自身的域名解析**（下载订阅、NTP、DoT/DoH 主机名）通过「引导 DNS」完成，不经过自己的过滤服务器，避免循环依赖。lwIP 编译时去掉了 DHCP 下发 DNS 的功能（`LWIP_DHCP_MAX_DNS_SERVERS=0`，见顶层 CMakeLists.txt），否则路由器把本设备设为 DNS 后，DHCP 续租会把设备自己的解析指向自己。没有配置引导 DNS 时使用网关地址。
- **OTA**：上传或 URL 方式。两种方式都会在擦除前检查固件的项目名；每写一块持有一次 Flash 锁（下载期间不会长时间挡住其他 Flash 写操作）。新固件运行 60 s 后才确认，在此之前崩溃会由 bootloader 回滚。
- **Web 安全**：浏览器发起的跨站 POST/PUT（带 `Origin` 且与 `Host` 不一致）一律返回 403，防止恶意网页借助浏览器缓存的密码修改设置；curl 等不带 `Origin` 的客户端不受影响。上传请求体时，客户端连续 30 s 不发数据就断开（httpd 是单任务的）。

## 8. 读代码的推荐顺序

从 `main/app_main.c` 看启动顺序，再读 `app_config.c` 的持久化结构、`main/net.c` 的 SoftAP/STA 状态切换。DNS 入站从 `dns_server_start` 进入 `dns_engine.c`，本地处理/过滤/缓存后在 `dns_server.c` 管理上游同步/异步结果；规则镜像在 `rules.c` 组织下载、编译、A/B 切换，过滤器实现本身在 `fl_filter`，与硬件解耦。DoT/DoH 上游在 `upstream_tls.c`，本机对外的 HTTPS DoH 在 `web.c`，对外 DoT 在 `dot_server.c`。

### 生命周期关键点

- 启动时先加载已有规则，再给缓存分配预算，降低启动规则镜像失败概率；如果镜像损坏，必须保留可恢复的网络管理通道。
- 规则更新期间 staging 的外排序与 inactive 镜像的写入受 Flash 空间限制；激活不能使旧规则还在处理查询时被提前释放。
- 重配 DNS 和重载过滤器可能触发缓存无效化，因而会影响首批查询的延迟。
- TLS 证书上传由 `web.c` 校验后写入 NVS，变更服务端需要在 HTTP 回调外安全重启/重载。
- `main/net.c` 的配置热点仅解决首次配网，不意味着开启无条件公网 DNS 访问。

## 9. 为什么代码与数据不全部放在 PSRAM？

片内 SRAM 需要承载网络驱动、DMA 兼容的缓冲、系统栈和部分高频小对象；PSRAM 要给规则索引、L2 缓存、TLS 大对象和规则更新工作区。Flash 保存持久规则镜像和固件，但 Flash 擦除/写入可能短暂影响共享缓存访问。`CONFIG_SPIRAM_XIP_FROM_PSRAM` 有助于减少代码/常量取指与 Flash 操作的冲突，**不能据此承诺写 Flash 对所有 DNS 任务完全无影响**。

## 10. 性能最敏感的三个点

**一、CPU 不应逐条扫描规则：** 普通名称使用已编译索引，复杂语法须先筛候选，恶意正则须限制计算规模。

**二、缓存命中必须尽量不阻塞：** SRAM 一级缓存负责小的热门应答，PSRAM 二级缓存存长尾；TTL 不能因为缓存优化被错误延长，缓存更新需要保证线程间一致性。

**三、失败路径必须短且有界：** 上游失败时避免无限重试、DoT/DoH 必须有连接超时、TCP 分段不可无限拖住工作线程，HTTP 上传要限长度。

## 11. 设计取舍与不做的事

本项目定位为独立 DNS 服务器，默认通过 Wi-Fi 连接现有网络，由路由器负责 DHCP 地址分配和互联网转发。详情请读 [README](../README.md) 与 [安全说明](TLS_AND_SECURITY.md)。
