## 4. 对抗测试：不仅测正常查询

### 4.1 不可信 DNS 报文

构造：长度不足 12 字节、QDCOUNT 过大、压缩指针环、超长标签、EDNS 大小不合理、重名问题、随机 opcode、未知 QTYPE、UDP TC、大 TCP 长度前缀、故意断开与慢速发送；检查目标是**无越界、无死锁、不会把不合法应答缓存、有限时间内拒绝或应答**。

### 4.2 不可信过滤订阅

测试：HTML 伪装文本、空列表、二进制 NUL、极长单行、非常大量重复、互相冲突的 `@@`/`$important`/`$badfilter`、跨列表例外、没有固定字面量的正则、超大镜像与 staging 耗尽、HTTP 断流及错误状态码。失败时应保留原有效镜像并在状态页有明确错误。

### 4.3 资源耗尽

在内存压力下反复打开 HTTP、TLS、DNS TCP 连接，规则更新同时进行；检查 task creation 失败有错误信息，且关键服务不因为一次申请失败触发无意义重启。尤其要观测**最大连续内部 SRAM**，而不只是总可用堆。

### 4.4 更新与断电

规则 A/B 提交前、写入 staging 中间、开始加载新镜像、更新 cfg、下载 HTTPS OTA 各阶段模拟突然断电；重启后应能选择合法固件及合法旧规则。软件模拟不能替代真实 Flash 掉电测试。

### 4.5 安全验证

无密码/已设置密码两种状态分别对敏感 API 做认证测试；跨域 POST、错误 HTTP 方法、超长 body、非法 JSON、错误证书与私钥、重复上传证书、备份中携带敏感字段、DoH 非法 Base64URL、缺少 `application/dns-message` 等应被安全处理。

## 5. 覆盖率结果与解释

本次 GCC gcov 覆盖率仅针对 Linux 可移植组件：**行覆盖 89.54%、分支覆盖 74.87%**。这些数字来自主机单元测试及随机压力测试。**未测试的 ESP-IDF 驱动、Web、NVS、OTA/TLS 服务端路径不能计入已覆盖范围**。

两项 CTest 通过率为 100%（117 个过滤引擎断言组、142 个 DNS 核心断言组），但 CTest 的 `2/2 passed` 不等于所有代码都被执行。全部详细统计和剩余风险见 [CODE_AUDIT.md](CODE_AUDIT.md)。

## 6. 新功能合入时必须新增哪些测试？

- 修改规则解析器：新增至少 1 个正例、1 个负例、1 个损坏输入、1 个跨订阅优先级回归用例。
- 修改缓存：检查 TTL 递减、刷新、负缓存、DO/CD 不串用、规则版本更新后不返回旧过滤结果。
- 修改上游：检查断连、重试、超时、重复包、错乱 ID、TCP 截断、TLS 名称验证。
- 修改 Web/API：检查无密码、有效凭据、无效凭据、跨站 Origin、超长报文与格式错误。
- 修改 OTA/Flash：新增实机恢复流程测试，确保新的分区表和旧配置不互相破坏。

测试报告应写**实际运行的平台与时间**，不可把上一个版本的测试结果直接复制成当前版本已验证结论。
